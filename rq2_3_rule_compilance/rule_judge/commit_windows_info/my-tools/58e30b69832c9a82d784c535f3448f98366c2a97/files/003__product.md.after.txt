# 功能
前期就只包含两个功能：

## 功能详情描述
### 合并 pdf 文件
- 用户选中 "合并 pdf 文件" 卡片，弹出一个模态框
- **文件选择方式**：
  - ~~点击选择文件按钮~~
  - ~~拖拽文件到指定区域~~
  - **实际实现**：使用 Electron 原生文件对话框选择文件（更可靠，避免浏览器环境限制）
- **文件管理**：
  - 显示已选文件列表（文件名、大小、状态）
  - ~~支持拖拽调整文件合并顺序~~
  - 可以删除已选文件
  - **实际实现**：文件状态包括 ready、invalid、processing、done、error 五种状态
  - **实际实现**：文件大小使用 formatFileSize 工具函数格式化显示
- **文件限制**：
  - 文件选中上限为10个
  - 单个文件大小不超过100MB，总大小不超过500MB
  - 只允许选择 .pdf 格式文件
  - 自动检测并提示损坏的PDF文件
  - **实际实现**：通过 Electron dialog 的 filters 属性限制文件类型
- **输出设置**：
  - 用户可以自定义输出文件名
  - 用户可以选择保存位置（默认为系统 downloads 目录）
  - 如果目标位置存在同名文件，提示用户选择覆盖或重命名
  - **实际实现**：使用 Electron 的 showSaveDialog 选择保存位置
  - **实际实现**：文件覆盖确认通过 showMessageBox 实现
- **处理过程**：
  - 显示合并进度条和百分比
  - 支持取消操作
  - 处理完成后显示成功提示和文件位置
  - **实际实现**：使用 pdf-lib 库进行真实的 PDF 合并
  - **实际实现**：通过 IPC 通信实现进度报告
  - **实际实现**：使用 React Toast (sonner) 显示操作结果通知

### 图片压缩
- 用户选中 "图片压缩"卡片，弹出一个模态框
- **文件选择方式**：
  - 点击选择文件按钮
  - 拖拽文件到指定区域
  - 支持批量选择多张图片
- **压缩设置**：
  - 压缩方式选择：按文件大小 / 按图片尺寸 / 按质量等级
  - 文件大小：可指定目标文件大小（如500KB以下）
  - 图片尺寸：可指定最大宽度或高度（如1920px）
  - 质量等级：高质量(90%) / 中等质量(70%) / 高压缩(50%)
- **文件支持**：
  - 输入格式：jpg, jpeg, png, webp
  - 输出格式：可选择保持原格式或转换为其他格式
- **输出设置**：
  - 用户可以选择保存位置（默认为系统 downloads 目录）
  - 批量处理时支持自定义文件名规则（如添加后缀 "_compressed"）
- **处理过程**：
  - 显示压缩进度和当前处理的文件
  - 显示压缩前后文件大小对比
  - 支持取消操作
  - 处理完成后显示压缩结果统计

# 实际开发记录

## PDF合并功能开发总结

### 技术架构决策
- **文件选择方式变更**：从拖拽上传改为 Electron 原生对话框
  - **原因**：浏览器环境中 File 对象缺少 path 属性，无法获取真实文件路径
  - **解决方案**：使用 `dialog.showOpenDialog` 获取文件路径数组
- **状态管理简化**：使用 React 内置 useState 而非第三方状态管理
  - **原因**：功能相对简单，不需要复杂的状态管理
- **通知系统选择**：最终采用 React Toast 而非系统通知
  - **原因**：系统通知在某些环境下不稳定，Toast 更可靠且样式统一

### 关键技术实现
- **IPC 通信模式**：
  - 主进程：处理文件操作、PDF合并、进度报告
  - 渲染进程：UI交互、状态管理、进度显示
- **文件处理流程**：
  1. 文件选择 → 2. 文件验证 → 3. PDF合并 → 4. 保存文件 → 5. 结果通知
- **错误处理策略**：
  - 文件级别错误：单个文件处理失败时继续处理其他文件
  - 系统级别错误：整个操作失败时显示友好错误信息
  - 用户操作错误：文件覆盖确认、取消操作支持

### UI/UX 优化
- **模态框布局**：采用固定头部/底部，可滚动中间内容的布局
- **进度反馈**：实时显示当前处理文件和整体进度
- **视觉一致性**：所有组件遵循统一的设计系统（圆角、间距、颜色）

### 性能考虑
- **内存管理**：大文件处理时的内存优化
- **进度报告**：避免过于频繁的进度更新影响性能
- **文件验证**：在合并前验证文件有效性，避免处理过程中失败

## 开发过程中的挑战与解决

### 挑战1：浏览器环境限制
- **问题**：Web环境中无法获取文件的真实路径
- **解决**：充分利用 Electron 的原生能力，使用系统对话框

### 挑战2：通知系统不稳定
- **问题**：系统通知在不同环境下表现不一致
- **解决**：改用应用内 Toast 通知，提供更好的用户体验

### 挑战3：TypeScript 类型问题
- **问题**：Vite 环境变量和 Node.js 类型定义冲突
- **解决**：添加必要的类型声明，配置 skipLibCheck
