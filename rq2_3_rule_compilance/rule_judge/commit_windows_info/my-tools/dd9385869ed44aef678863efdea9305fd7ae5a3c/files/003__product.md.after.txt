# 实际开发记录

## PDF合并功能开发总结

### 技术架构决策
- **文件选择方式变更**：从拖拽上传改为 Electron 原生对话框
  - **原因**：浏览器环境中 File 对象缺少 path 属性，无法获取真实文件路径
  - **解决方案**：使用 `dialog.showOpenDialog` 获取文件路径数组
- **状态管理简化**：使用 React 内置 useState 而非第三方状态管理
  - **原因**：功能相对简单，不需要复杂的状态管理
- **通知系统选择**：最终采用 React Toast 而非系统通知
  - **原因**：系统通知在某些环境下不稳定，Toast 更可靠且样式统一

### 关键技术实现
- **IPC 通信模式**：
  - 主进程：处理文件操作、PDF合并、进度报告
  - 渲染进程：UI交互、状态管理、进度显示
- **文件处理流程**：
  1. 文件选择 → 2. 文件验证 → 3. PDF合并 → 4. 保存文件 → 5. 结果通知
- **错误处理策略**：
  - 文件级别错误：单个文件处理失败时继续处理其他文件
  - 系统级别错误：整个操作失败时显示友好错误信息
  - 用户操作错误：文件覆盖确认、取消操作支持

### UI/UX 优化
- **模态框布局**：采用固定头部/底部，可滚动中间内容的布局
- **进度反馈**：实时显示当前处理文件和整体进度
- **视觉一致性**：所有组件遵循统一的设计系统（圆角、间距、颜色）

### 性能考虑
- **内存管理**：大文件处理时的内存优化
- **进度报告**：避免过于频繁的进度更新影响性能
- **文件验证**：在合并前验证文件有效性，避免处理过程中失败

## 开发过程中的挑战与解决

### 挑战1：浏览器环境限制
- **问题**：Web环境中无法获取文件的真实路径
- **解决**：充分利用 Electron 的原生能力，使用系统对话框

### 挑战2：通知系统不稳定
- **问题**：系统通知在不同环境下表现不一致
- **解决**：改用应用内 Toast 通知，提供更好的用户体验

### 挑战3：TypeScript 类型问题
- **问题**：Vite 环境变量和 Node.js 类型定义冲突
- **解决**：添加必要的类型声明，配置 skipLibCheck

## 图片压缩功能开发总结

### 技术架构决策
- **原生模块集成挑战**：Sharp 库在 Electron 环境中的加载问题
  - **问题**：Sharp 是原生模块，Vite 打包时无法正确处理动态加载
  - **解决方案**：配置 Vite 外部依赖 + 动态导入 `await import('sharp')`
- **文件选择方式统一**：沿用 PDF 合并的成功经验
  - **原因**：Electron 原生对话框比浏览器文件选择更可靠
  - **实现**：`dialog.showOpenDialog` 支持图片格式过滤
- **压缩算法选择**：优先实现按质量等级压缩
  - **原因**：用户最常用的压缩方式，技术实现相对简单

### 关键技术实现
- **Sharp 动态加载**：
  ```typescript
  const sharp = await import('sharp');
  const sharpInstance = sharp.default(filePath);
  ```
- **Vite 配置优化**：
  ```typescript
  // vite.main.config.ts
  export default defineConfig({
    build: {
      rollupOptions: {
        external: ['sharp']
      }
    }
  });
  ```
- **多格式支持**：JPEG、PNG、WebP 的质量压缩适配
- **文件处理流程**：
  1. 文件选择 → 2. 格式检测 → 3. 质量压缩 → 4. 格式转换 → 5. 保存文件

### 压缩功能特性
- **按质量等级压缩**：10%-100% 可调节质量滑块
- **格式转换支持**：保持原格式或转换为 JPG/PNG/WebP
- **文件名后缀自定义**：默认添加 "_compressed" 后缀
- **重名文件处理**：集成应用配置，支持自动编号或询问覆盖
- **批量处理**：支持多文件同时压缩
- **错误容错**：单文件失败不影响其他文件处理

### 开发过程中的挑战与解决

#### 挑战1：Sharp 库加载失败
- **问题**：`Could not load the "sharp" module using the darwin-arm64 runtime`
- **根本原因**：Vite 打包时将 Sharp 打包进 bundle，导致原生模块路径错误
- **解决方案**：
  1. 配置 Vite 将 Sharp 作为外部依赖
  2. 使用动态导入而非静态导入
  3. 将 Sharp 安装为 devDependencies

#### 挑战2：代码一致性维护
- **问题**：用户部分撤销修改导致函数调用不匹配
- **解决**：
  1. 移除未定义的 `handleDrop` 函数调用
  2. 修复文件选择按钮的事件绑定
  3. 确保状态变量与使用场景匹配

#### 挑战3：Lint 警告处理
- **问题**：未使用的变量和导入产生警告
- **解决**：平衡代码简洁性与功能完整性，保留必要的预留代码

### UI/UX 优化
- **简化交互流程**：移除复杂的拖拽功能，专注核心压缩功能
- **状态反馈**：文件状态显示（准备就绪、处理中、已完成、处理失败）
- **设置面板**：直观的质量滑块和格式选择
- **错误处理**：友好的错误提示和 Toast 通知

### 性能考虑
- **内存优化**：Sharp 按需动态加载，避免启动时加载
- **处理效率**：利用 Sharp 的高性能图片处理能力
- **错误恢复**：单文件处理失败时继续处理队列中的其他文件

  - 操作时间戳
  - 输入文件信息（文件名、大小、路径）
  - 输出文件信息（文件名、路径、大小）
  - 操作设置参数
  - 操作耗时
  - 操作结果（成功/失败）
  - 错误信息（如果失败）
- **用户界面**：
  - 主界面右上角"操作历史"按钮
  - 模态框显示历史记录列表
  - 成功操作显示绿色背景，失败操作显示红色背景
  - 支持查看详细信息、打开文件位置
  - 支持删除单条记录或清空所有记录
- **技术实现**：
  - HistoryManager 类管理历史记录的增删改查
  - 最多保存100条记录，超出时自动删除最旧记录
  - IPC 通信实现主进程与渲染进程的数据交互
  - 完整的 TypeScript 类型定义

  - 模态框显示配置选项
  - 开关控制，实时示例展示
  - 支持保存、重置为默认值
- **技术实现**：
  - ConfigManager 类管理配置的读取、更新、重置
  - 配置持久化保存，重装应用后配置保留
  - 所有工具自动应用配置设置
  - 默认配置：自动添加序号功能开启
